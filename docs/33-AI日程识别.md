# 33 · 日程识别交接（Harness）

> 2026-11-08 更新：日程识别改为「产品侧只留闸门与文件交接，读图交给本机 DSH 会话」。
> 产品进程不再直连任何视觉模型：`shared/ai.py`、`config/ai.env` 模板，以及管理台的模型配置、
> 连通性测试、立即识别入口都已删除，安装时也不再生成 `config/ai.env`。
> 历史直连方案与样例分析见 [21-周表动态识别可行性分析.md](21-周表动态识别可行性分析.md)
> （历史文档，其中的模型配置已不适用）。
> 管理台「日程表」页的「定时识别」条与「日程识别模型」卡已于同日从前端移除，
> 现在只剩候选池、人工定性卡片和日程表本身。
> **默认关闭**：首次配置的项目不会跑本页任何流程。在「监控名单」的添加框输入 `weekly_open` 点「添加」
> 才会开启（等价 `POST /api/weekly/feature {"enabled":true}`），此时守护进程拉起日程进程组，
> 管理台也才显示「日程表」页、监控名单的「日程」列与进程页的该分组；输入 `weekly_close` 关闭并收起进程组。
> 开关存 `meta['weekly_feature_enabled']`，没有这个键就是关闭状态。

## 1 它是怎么工作的

```text
动态采集 ──► weekly_candidate（候选池，status=pending）
                 │
                 │  闸门：总开关开 + 有待确认候选 +
                 │        到时段（08:00 / 13:00 / 19:00 / 00:00）或人工排队
                 ▼
        harness_export（core/weekly/agent.py）
                 │  组装素材（正文 + 周表图绝对路径 + 字数/时间提示 + 同主播近期场次）
                 │  写成 out/ai_tasks/<batch_id>.json
                 ▼
        本机 DSH 会话（手动把提示词丢进去，或 DSH 定时自动化）
                 │  按任务里的 instructions 读图判读
                 │  把结果写到 out/ai_results/<batch_id>.json
                 ▼
        harness_ingest
                 │  校验 → normalize → weekly.store.ingest
                 ▼
        weekly_schedule ──► 管理台「日程表」页 + 每日 08:10 推送 + livedeck
```

关键点：产品进程只读写文件与数据库，**不发任何模型请求**，不需要 base_url、key、模型名。
判图质量取决于你当前 DSH 会话的模型；2026-11 实测它能读周表小字和候选卡缩略图。

闸门开关（落库 meta，用 `python scripts/weekly_ai.py set …` 改）：

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 总开关 `weekly_ai_enabled` | 开 | 关掉后不导出任务，也不处理人工排队 |
| 时段 `weekly_ai_slots` | `08:00,13:00,19:00,00:00` | 一天导出几次 |
| 每轮条数 `weekly_ai_limit` | 12 | 一个任务包里最多几条候选 |
| 人工排队 `weekly_ai_request_at` | 0 | 写入时间戳后，下一轮立刻导出一次（不受时段限制） |

日程进程组（`scripts/schedule_worker.py`）每 5 分钟跑一轮 `weekly_agent_loop`：先回收结果，再看闸门决定要不要导出。
进程页的「日程识别交接」（`weekly_agent`）暂停的是这个循环；暂停后手动命令行照样可用。

## 2 交接契约（目录与文件）

```text
out/ai_tasks/<batch_id>.json          待判任务：素材 + 图片绝对路径 + 输出格式说明
out/ai_results/<batch_id>.json        会话写回的结果 {"results": [...]}
out/ai_results/<batch_id>.error.json  会话判不了时写的失败说明
out/ai_tasks/done/ 、out/ai_results/done/   入库成功后自动归档，供事后核对
```

任务文件的主要字段：`contract`（`bbot.weekly-ai/1`）、`batch_id`、`created_at`、`project_root`、
`instructions`（判读规则，含三种 scope、强制二次判读、时间口径）、`output_file`、
`items[]`（`event_id` / `uid` / `uname` / `posted_at` / `images` / `material`）。

给会话的提示词只需要一句话（任务里的 instructions 已经写全）：

> 读 out/ai_tasks/ 下未处理的 JSON 任务，按里面的 instructions 逐条读图判读，
> 把结果按 output_file 指定的路径写成 results 数组；判不了就写同名 .error.json。
> 写完后删除任务文件。

结果文件按任务里的 schema 写；最少要带 `event_id` 和 `is_schedule` / `scope` 等判读字段，
`confidence`、`recheck`、`week` / `single` 的明细越全，入库后越少进复核。

## 3 手动走一遍

1. `python scripts/weekly_agent.py export` 写任务文件（`out/ai_tasks/<batch_id>.json`），
   终端会打印路径与提示词；先看一眼可以加 `--dry-run`，只打印不落盘。
2. 把提示词（或任务路径）丢给 DSH 会话，等它读完图并写出 `out/ai_results/<batch_id>.json`。
3. `python scripts/weekly_agent.py ingest` 回收并入库。
4. 终端会打印「回收 N 条 / 入库 M 条 / 复核 K 条」；日程进程组每轮也会自动回收，不必等下一次时段。

命令行全集：

```bash
python scripts/weekly_agent.py status             # 开关/时段/队列/上次结果/任务统计
python scripts/weekly_agent.py export --limit 6   # 只导出 6 条
python scripts/weekly_agent.py export --dry-run   # 只打印将要导出的任务
python scripts/weekly_agent.py ingest --dry-run   # 只校验、不入库
python scripts/weekly_ai.py gate                  # 现在该不该跑、为什么
python scripts/weekly_ai.py request               # 人工排队，下一轮立即导出
```

等价 HTTP 接口（管理台已不调用，脚本/第三方可用）：`POST /api/weekly/agent/export`、
`POST /api/weekly/agent/import`、`POST /api/weekly/ai/run`（人工排队）、
`PATCH|POST /api/weekly/ai`（改开关/条数/时段）、`GET /api/weekly/agent`（状态）。

## 4 定时走一遍（DSH 自动化）

在 DSH 里新建一条 automation，建议：

- 频率：每 5 分钟（最短 1 分钟，但会话有成本，别太密）；
- 权限：workspace-write（要写 `out/ai_results/`、删任务文件）；
- 提示词：用 `core/weekly/harness.py` 的 `automation_prompt(root)`（或 §2 末尾那句话）。

到点后它扫任务目录 → 读图 → 写结果 → 删任务；日程进程组每轮先回收结果文件
（`weekly_agent_loop` 在 gate 判断前调用 `harness_ingest`），所以不用等下一次导出时段。

## 5 校验与失败处理

结果文件不会照单全收，入库前过三道检查：

| 检查 | 不通过时 |
| --- | --- |
| JSON 能否解析（允许夹说明文字、围栏块） | 整段丢弃，提示「结果格式不对」 |
| 每条必须有 event_id | 记「第 N 条缺 event_id」，该条丢弃 |
| event_id 必须在这批任务里、且不重复 | 记「不在这次任务里」/「重复」，该条丢弃 |

有问题的批次**不归档**，任务和结果文件留在原地，改完重新导入即可。

## 6 结果长什么样 / 怎么复核

会话只能给出**结构化判读**，落库前统一洗一遍（`agent.normalize`）：字段缺失就丢、
置信度夹到 0~1、`is_schedule` 认中英文真假值、`scope` 只认 `week` / `single` / `none`，
`extractor` 记为 `harness`。

判读结果里有两块会影响入库：

- **`confidence` < 0.7**、周表天数不足、周次是猜的 → 进「待复核」队列，不直接当准数；
- **`recheck`**：要求会话**二次确认**这张图到底是不是本周周表。
  `confirmed` 正常入库；`downgraded`（看了半天其实是旧图 / 不是日程）直接标 `none`；
  `unsure` 进复核。手写体、截图带聊天气泡这类容易误判的，都会落到这里。

人工永远压过自动判读：在候选卡片上点「本周周表 / 单场 / 不是日程」写的是
`weekly_candidate.human_scope`，之后会话再判也不会覆盖人工定性质。

## 7 失败排查

`python scripts/weekly_agent.py status` 会打印开关、`gate`、`next_run`、上次结果和
`harness` 统计（tasks / results / done），先看这里：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 一直是「待确认」不导出 | 总开关关了 / 没到时段 / 没候选 / 进程页暂停了 | 看 `gate.reason` 与 `next_run`；人工排队用 `weekly_ai.py request` |
| 有任务文件但没人读 | 没把提示词丢给会话，或 DSH 自动化没启 | 手动跑一次会话；检查 automation 的任务与权限 |
| `导入` 返回 1 或「结果格式不对」 | 结果 JSON 坏了 / 文件不在 `out/ai_results/` | 让会话重写；确认文件名与 `batch_id` 一致 |
| 「第 N 条缺 event_id」 | 结果条目缺 `event_id` | 按任务 items 补上，否则该条丢弃 |
| 「不在这次任务里」/「重复」 | `event_id` 抄错或重复 | 对照任务文件改；有问题的批次不会归档 |
| 结果一直不回收 | 日程进程组没跑 / 进程页暂停了 | 看进程页「日程进程组」状态；重启服务，或手动 `weekly_agent.py ingest` |

原始日志：`logs/`（主进程）与管理台「日志」页；候选图路径在任务文件的 `items[].images` 里。

## 8 关掉它

按粒度选：

```powershell
# 只关自动导出，人工仍可用
python scripts/weekly_ai.py set --enabled 0
# 关掉日程进程组里的导出/回收循环（重启进程后仍生效，开关落库）
#   管理台 → 进程页 → 日程识别交接 → 关
```

完全不跑导出，候选会一直堆在「待确认」，不会丢数据。旧的 `config/ai.env` 已经没有任何代码读取，
可以直接删掉。

## 9 隐私与安全

- 图片**不会发给任何模型服务**：只有你本机的 DSH 会话按任务里的绝对路径读取。
- 任务与结果文件都在 `out/`（已被 `.gitignore` 排除），里面只有图片路径与判读文本，没有凭据。
- 会话输出只当「候选判读」，不是事实来源：入库前有置信度门槛，人工随时可改。
- 如果让 DSH 自动化在云端模型上跑，图片会随会话上下文进入该模型服务——这取决于你选的会话模型，
  与监控台本身无关；介意就用手动方式在本机模型上判。
